# Nginx 反向代理验证说明

## 项目概述

本项目是一个基于 Nginx 的 Web 服务器配置，实现了本地静态资源服务和远程服务器反向代理功能。

## 目录结构

```
f:\WORK\tool\python\python\windows\web\
├── conf/                   # 配置文件目录
│   ├── nginx.conf         # 本地 Nginx 主配置文件
│   ├── nginx.conf.bak     # 配置文件备份
│   ├── nginx_remote.conf  # 远程服务器配置文件
│   └── mime.types         # MIME 类型定义
├── logs/                   # 日志目录
│   ├── access.log         # 访问日志
│   ├── error.log          # 错误日志
│   └── nginx.pid          # 进程 ID 文件
├── www/                    # 本地静态资源目录
│   └── index.html         # 本地首页
├── www_remote/             # 远程版本静态资源目录
│   └── index.html         # 远程版本首页
└── nginx.exe              # Nginx 可执行文件
```

## 配置文件说明

### 1. nginx.conf（本地配置）

**功能**：本地 Nginx 服务器，监听 8081 端口

```nginx
worker_processes  1;                    # 工作进程数
error_log  logs/error.log info;         # 错误日志路径和级别

events {
    worker_connections  1024;           # 每个进程最大连接数
}

http {
    server {
        listen      8081;               # 监听端口
        
        # 本地静态资源服务
        location / {
            root www;                   # 静态文件根目录
        }
        
        # 远程服务器反向代理
        location /remote/ {
            proxy_pass http://192.168.13.166:8081/;    # 远程服务器地址
            proxy_set_header Host $host;               # 传递原始 Host 头
            proxy_set_header X-Real-IP $remote_addr;   # 传递真实客户端 IP
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;  # 传递代理链 IP
        }
    }
}
```

**路径映射规则**：

| 访问路径 | 实际指向 | 说明 |
|---------|---------|------|
| `http://localhost:8081/` | `www/index.html` | 本地首页 |
| `http://localhost:8081/index.html` | `www/index.html` | 本地首页 |
| `http://localhost:8081/remote/index.html` | `http://192.168.13.166:8081/index.html` | 远程首页（通过代理） |

### 2. nginx_remote.conf（远程配置）

**功能**：远程 Nginx 服务器配置，部署在 192.168.13.166

```nginx
worker_processes  1;
error_log  logs/error.log info;

events {
    worker_connections  1024;
}

http {
    server {
        listen      8081;
        
        location / {
            root www_remote;            # 使用 www_remote 目录
        }
    }
}
```

## 反向代理工作原理

```
用户浏览器
    ↓ 请求 http://localhost:8081/remote/index.html
本地 Nginx (localhost:8081)
    ↓ 匹配 location /remote/，去掉 /remote/ 前缀
    ↓ 转发到 http://192.168.13.166:8081/index.html
远程 Nginx (192.168.13.166:8081)
    ↓ 匹配 location /，在 www_remote 目录查找
返回 www_remote/index.html
```

## 关键配置点

### proxy_pass 路径处理

```nginx
location /remote/ {
    proxy_pass http://192.168.13.166:8081/;    # 末尾有斜杠
}
```

- `location /remote/` 匹配以 `/remote/` 开头的请求
- `proxy_pass` 末尾的 `/` 表示去掉匹配的 `/remote/` 部分
- 用户访问 `/remote/index.html` → 代理到 `/index.html`

### 请求头传递

| 请求头 | 作用 |
|-------|------|
| `Host` | 传递原始域名，用于虚拟主机识别 |
| `X-Real-IP` | 传递真实客户端 IP |
| `X-Forwarded-For` | 传递完整的代理链路 IP 列表 |

- **本地服务器**：运行 `nginx.conf`，监听 8081 端口
- **远程服务器**：192.168.13.166，运行 `nginx_remote.conf`，监听 8081 端口

## 测试前准备

### 1. 确认静态资源文件

确保以下文件存在且有不同内容，便于区分：

```powershell
# 本地首页（普通版本）
type www\index.html

# 远程首页（remote 版本）
type www_remote\index.html
```

**建议**：在 `www_remote\index.html` 的 `<title>` 或 `<h1>` 中加入 "Remote" 字样，方便识别。

### 2. 启动远程服务器（192.168.13.166）

```powershell
cd <远程服务器路径>
.\nginx.exe -c conf/nginx_remote.conf
```

验证远程服务器启动成功：
```powershell
tasklist | findstr nginx
curl http://192.168.13.166:8081/index.html
```

### 3. 启动本地服务器

```powershell
cd f:\WORK\tool\python\python\windows\web
.\nginx.exe
```

验证本地服务器启动成功：
```powershell
tasklist | findstr nginx
curl http://localhost:8081/index.html
```

## 测试用例

### 测试 1：本地静态资源访问

**目的**：验证本地静态资源服务正常

**步骤**：
1. 浏览器访问：`http://localhost:8081/`
2. 或命令行测试：`curl http://localhost:8081/index.html`

**预期结果**：
- 返回 `www/index.html` 的内容（普通版本）
- HTTP 状态码：200

**验证方法**：
```powershell
curl -I http://localhost:8081/index.html
# 应返回 HTTP/1.1 200 OK
```

---

### 测试 2：反向代理访问远程资源

**目的**：验证反向代理配置正确，能访问远程服务器

**步骤**：
1. 浏览器访问：`http://localhost:8081/remote/index.html`
2. 或命令行测试：`curl http://localhost:8081/remote/index.html`

**预期结果**：
- 返回远程服务器的 `www_remote/index.html` 内容（remote 版本）
- HTTP 状态码：200
- 页面内容应与直接访问 `http://192.168.13.166:8081/index.html` 一致

**验证方法**：
```powershell
# 通过代理访问
curl http://localhost:8081/remote/index.html

# 直接访问远程服务器
curl http://192.168.13.166:8081/index.html

# 两者内容应该相同
```

---

### 测试 3：路径处理验证

**目的**：验证 `proxy_pass` 的路径去掉逻辑正确

**步骤**：
1. 直接访问远程服务器的根路径：`http://192.168.13.166:8081/`
2. 通过代理访问：`http://localhost:8081/remote/`

**预期结果**：
- 两者返回相同的内容（都是 remote 版本首页）
- 说明 `/remote/` 被正确去掉，代理到远程的 `/`

**验证方法**：
```powershell
curl http://192.168.13.166:8081/
curl http://localhost:8081/remote/
```

---

### 测试 4：错误处理测试

**目的**：验证 404 错误处理

**步骤**：
1. 访问不存在的本地文件：`http://localhost:8081/notexist.html`
2. 访问不存在的远程文件：`http://localhost:8081/remote/notexist.html`

**预期结果**：
- 两者都返回 HTTP 404 错误
- 本地错误记录在 `logs/error.log`

**验证方法**：
```powershell
curl -I http://localhost:8081/notexist.html
# 应返回 HTTP/1.1 404 Not Found

type logs\error.log
```

---

### 测试 5：请求头传递验证

**目的**：验证代理请求头正确传递

**步骤**：
在远程服务器上创建一个测试脚本（如 PHP 或 Python），输出接收到的请求头。

**或使用浏览器开发者工具**：
1. 打开浏览器开发者工具（F12）
2. 切换到 Network 标签
3. 访问 `http://localhost:8081/remote/index.html`
4. 查看请求头中是否包含：
   - `Host: localhost:8081`
   - `X-Real-IP: 127.0.0.1`（或你的真实 IP）
   - `X-Forwarded-For: 127.0.0.1`（或你的真实 IP）

## 故障排查

### 问题 1：访问 `/remote/` 返回 404

**排查步骤**：
```powershell
# 1. 检查远程服务器是否运行
curl http://192.168.13.166:8081/index.html

# 2. 检查本地 Nginx 配置语法
.\nginx.exe -t

# 3. 检查错误日志
type logs\error.log
```

**可能原因**：
- 远程服务器未启动
- `proxy_pass` 路径配置错误（缺少或多余斜杠）
- 防火墙阻止连接

---

### 问题 2：访问 `/remote/` 返回本地内容

**排查步骤**：
```powershell
# 检查配置中 location 顺序
# location /remote/ 必须在 location / 之前
```

**可能原因**：
- `location /` 匹配了所有请求，导致 `/remote/` 无法匹配
- 配置未重新加载

**解决方法**：
```powershell
.\nginx.exe -s reload
```

---

### 问题 3：远程服务器返回的内容不对

**排查步骤**：
```powershell
# 在远程服务器上检查
cd <远程服务器路径>
dir www_remote
type www_remote\index.html
```

**可能原因**：
- 远程服务器使用的是 `www` 目录而非 `www_remote`
- 远程服务器配置未生效

**解决方法**：
```powershell
# 远程服务器上执行
taskkill /F /IM nginx.exe
.\nginx.exe -c conf/nginx_remote.conf
```

## 使用场景

1. **本地开发**：访问本地静态资源进行开发调试
2. **远程代理**：通过 `/remote/` 路径访问远程服务器资源，无需修改前端代码
3. **负载均衡扩展**：可在 `upstream` 中配置多个远程服务器实现负载均衡
4. **API 代理**：可将 `/api/` 路径代理到后端服务（如 Python Flask/FastAPI）
